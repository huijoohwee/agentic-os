# Bounded generation

## GENERATION-001@1.0.0: purpose and acceptance

A solo builder repeatedly rebuilds unchanged artifacts during an MVP/GTM sprint. The builder
(role/subject) reuses (action/verb) verified generated bytes (object), reducing repeat work while
keeping source ownership and release checks current. Acceptance: repeated inputs skip the producer;
changed source, options, tool versions or output bytes invalidate reuse; generation fails before
publishing oversized output; receipts do not accumulate by content hash. Buyer WTP remains untested.

## Design and decision

Import `agentic-os/generation` explicitly in Node build tools. The package root and browser runtime
do not import it. This single on-demand module adds no dependency, service, watcher or scheduler.
`generationManifest(root, {paths, exclude, ...limits})` streams file hashes with a 64 KiB buffer,
deterministic ordering and explicit entry, depth, byte and elapsed-time limits. Exclusions belong
to the source owner; symlinks and special files fail. Limits never silently truncate the manifest.

`generateFile({destination, receipt, inputs, produce, ...limits})` stores one small receipt for one
declared output. `inputs()` must freshly identify every source file, generator, lockfile, tool
version, public build option and relevant environment setting. The helper additionally binds Node,
platform and architecture. It rehashes the current output before reuse and rechecks inputs. A miss
calls `produce({signal})`, validates its returned buffer, then atomically replaces the generated file
and fixed receipt. It never stores a second artifact copy or a history of cache keys. Independent
outputs require different receipt paths. Do not derive receipt filenames from changing input hashes.

The output lock rejects concurrent cooperative writers instead of polling. Producers must return
bytes without writing files and honor AbortSignal for cancellation. The deadline prevents late
publication; synchronous work and OS I/O require cooperative checks and cannot be forcibly preempted.
Inputs are observed snapshots, not atomic filesystem transactions. Reuse receipts are local performance
hints, never signing, payment, deployment, admission or other authority evidence. Do not put secrets
in keys or receipt fields. An interrupted receipt write causes a fresh generation on the next run.

`writeGeneratedFile(path, bytes, limits)` provides the same pre-publication bound, lock, atomic write
and identical-byte skip when a generator is cheap enough not to warrant an input cache.

Defaults: 10,000 entries, 256 MiB aggregate input, 64 MiB per input file, depth 32, 30 seconds,
499,999 output bytes, 16 KiB per receipt. Consumers set narrower or explicitly justified limits.
Generated outputs and receipts stay in owner-controlled ignored directories. Recovery archives
remain in the separately configured private storage root with hold retention; cache invalidation
never deletes recovery data. A same-disk archive does not provide independent disaster recovery.
