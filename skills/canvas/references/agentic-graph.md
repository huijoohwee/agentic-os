# Agentic Graph adapter

Use the selected product's pinned source and existing canvas runtime. Resolve source roots
from the host or installed package, not from ancestor-directory guesses. The current ownership
map is [TECH-STACK](../../../guides/TECH-STACK.md); read its division of work when routing changes.

For existing widget/document authoring, inspect the selected widget contract, source frontmatter
and Graph parser/rendering owner before editing. For application composition, read ACOS's
`docs/APPLICATION-COMPOSITION.md` at the consumer's accepted revision: its manifest/catalog/plan
contract delegates execution to registered Graph owners. Do not invent a parallel React renderer,
new invocation vocabulary or an executable tool from catalog metadata.

Resolve `/`, `#` and `@` through the existing `agentic-os/invocation` package and product discovery
surface. A dictionary entry is discovery metadata; verify that the requested runtime capability
exists and is available before invoking it. Preserve source identifiers and source-bound evidence.

Run the owning source's applicable parser, schema, renderer and product checks. Inspect actual
mobile and desktop behavior through the existing product preview. Keep source test results,
deployed version/readback and live commerce receipts distinct. Follow the product's publication
workflow if publication is requested; this adapter creates no deployment authority.
