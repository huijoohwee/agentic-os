# Structured document capability

Use this reference when the user supplies an existing document, widget, diagram or canvas
format and the environment exposes its source contract and renderer. Inspect the existing
artifact and accepted schema before editing. Preserve source identifiers, metadata, links,
units and user-authored content; change only the task's scope.

Discover the current format, supported operations, storage location and preview/validation
interface from the supplied environment. Do not invent an extension, component, tool name
or schema field. If the format has an SDK, consult its current public interface rather than
embedding its implementation or instructions into this reusable skill.

Keep source authoring, rendering and executable actions with their existing owners. A widget
catalog or composition plan describes capabilities; it does not establish their availability,
authorization or successful execution. Inspect the actual capability before using it.

Validate the changed source with the available schema/parser checks and inspect the rendered
result. Verify readable narrow/wide layouts and the affected interactions where supported.
If only source validation is available, report that limit. An exported snapshot should retain
its source identity and observation time without disclosing credentials or private identifiers.

Use the existing artifact's save/export workflow. Follow its publication contract only when
publication is requested. If the requested renderer is missing, retain the original artifact
and explain the limitation; do not silently replace its format with a different application.
